01 · THE PROBLEM

When the hand occludes a tool, even the right pose can look wrong.

To understand how a tool is being used, we want to estimate its 6-DoF pose over time. State-of-the-art methods do this by render-and-compare: render the object at a hypothesized pose, compare with observation image, update the hypothesized pose, repeat.

That works when the object is fully visible. A hand-held tool is not. Tools are thin, symmetric and often textureless, and are frequently occluded by the hand during manipulation. This means even at the correct pose, a render of the whole tool looks nothing like the occluded observation, so the comparison itself misleads the tracker.

02 · THE INSIGHT

The hand mask offers clues about where the tool is hidden.

As Figure 1 shows, we cannot see the whole fork, but we know it continues behind the fingers. The object mask says which pixels the projected tool should cover. The hand mask says where the hidden part may extend. A hand silhouette knows three things:

1Where the hidden pixels can be

The hand is the dominant occluder. Knowing its mask lets the model conjecture where the tool's occluded pixels are.

2Where the tool is going

The hand causes the tool's motion, so knowing where the hand is helps track the tool across frames.

3How the tool is turned

The hand holds the tool. Its silhouette carries cues about the grasp, and the grasp about the tool's orientation.

We use hand masks, not hand pose estimates, which we found to be noisy (see the ablation).

03 · THE METHOD

Hand and object masks guide pose refinement.

We build on FoundationPose. Its refinement network compares a rendered RGB-D crop with the observed one and predicts a rotation and translation update. It runs on every frame, so that is the part we change; the first-frame scoring network is left as is.

For each frame we segment the object and the hand with Grounding DINO and SAM 2, crop both masks with the same pose-dependent crop as the image (2 × 160 × 160), and encode them with a three-layer convolutional branch into a 512 × 20 × 20 map that is simply added to the fused image features.

We initialise from FoundationPose and fine-tune on the HOI4D training set, holding out 5% of the clips (66) for validation. We use object meshes reconstructed with BundleSDF for fine-tuning, validation, and testing. We keep the epoch-1 checkpoint, which had the lowest overall relative pose error on the validation clips.

04 · THE SILHOUETTE LOSS

A silhouette loss for pose refinement under occlusion.

Beyond conditioning on hand and object masks, we also supervise the refined pose with a differentiable silhouette loss. We sample P = 512 points from the mesh surface, project them into the image crop using the refined pose. We use the resulting pixel coordinates uk to compute the coverage and outside loss terms.

Coverage — the projected tool must cover every visible tool pixel

05 · MOCAP TOOLS DATASET

A benchmark of egocentric tool use.

Egocentric datasets are full of tool use but have no ground-truth object pose; pose benchmarks have ground-truth but few hand-held tools. MoCap Tools is our validation set for exactly that gap.

08 · ABLATIONS

Do the hand and object masks help?

Each mask alone improves translation but leaves rotation flat or worse. Together they lower every error but one.

Does explicit hand pose help?

Adding explicit hand geometry on top of both masks — wrist pose or 21 hand joints from MINT, a state-of-the-art hand pose estimator — does not help (last two rows of Table 2). Masks are a simpler and more effective signal, directly capturing the hand-object occlusion patterns not explicitly represented by hand poses.

Does the silhouette loss help?

Table 1 shows that incorporating the silhouette loss improves or maintains performance on all but one metric. This suggests that explicitly constraining the projected object geometry using hand and object masks provides useful supervision beyond the refiner's existing training objective.

Does the segmenter matter?

We train an additional model using hand masks generated by SAM 3 while keeping all other settings unchanged. We also generate evaluation masks using SAM 3, yielding four training–evaluation combinations. Performance is comparable across them and above both FoundationPose variants on most metrics.
